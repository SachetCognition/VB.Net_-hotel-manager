1. Purpose & Scope

1.1 Purpose

This User Requirement Specification (URS) formally catalogs every business function present in the legacy Hotel Management System (HMS) desktop application. It serves as the single source of truth to ensure zero functionality is deprecated during migration, except where explicitly listed in the Deprecated Features section.

1.2 Migration Scope

AspectLegacy (Current)Target (Modern)
LanguageVB.NET (Windows Forms)C# (.NET 8+)
Framework.NET Framework 4.0ASP.NET Core 8 Web API
DatabaseMicrosoft Access (.accdb via OleDb)SQL Server (via EF Core)
ReportingCrystal ReportsModern reporting (PDF/Excel generation)
ArchitectureMonolithic desktop (WinForms)Layered REST API (Clean Architecture)
AuthenticationBase64 "encryption" (ModFunc.vb)bcrypt/Argon2 password hashing + JWT
Excel ExportCOM Interop (Microsoft.Office.Interop.Excel)ClosedXML / EPPlus (no Office required)

1.3 Objectives

  • Migrate all business logic with identical functional behavior
  • Preserve all tax calculation formulas exactly as implemented
  • Maintain all data validation rules and business constraints
  • Replicate all 16 Crystal Reports as modern PDF/Excel equivalents
  • Ensure zero data loss during database migration
  • Improve security posture (password hashing, parameterized queries, RBAC)

2. Glossary

TermDefinition
GuestA person who stays at or uses hotel facilities. Identified by a unique GuestID (format: "G-" + 6 random digits).
ReservationA future booking of a room, hall, or garden for a guest, stored in the Temp_Reservation table. Status: "Reserved".
Check-InThe process of a guest occupying a room. Creates a record in CheckIn_Room with status "Checked In".
Check-OutThe process of a guest vacating a room with final bill generation. Creates a record in Checkout_Room.
RoomA hotel accommodation unit with RoomNo (PK), RoomType (AC/Non-AC/Deluxe/Suite), and RoomCharges.
OrderA food/beverage order placed by a checked-in guest or restaurant patron.
TransactionA financial transaction recorded against a guest or the hotel.
EmployeeA hotel staff member. Identified by EmployeeID (format: "E-" + 6 random digits).
InventoryFood, beverage, beer, and liquor items available for order/sale.
StockCurrent quantity levels of inventory items.
HallA hotel event/conference hall available for reservation with per-day charges.
GardenA hotel garden venue available for reservation with per-day charges.
Extra BedAn additional bed that can be added to a room during check-in at a configured charge.
Service TaxA percentage-based tax applied on the SubTotal of a booking.
Luxury TaxA percentage-based tax applied on (SubTotal + ServiceTaxAmount).
Education CessA secondary tax = ServiceTaxPer × 2 / 100, applied on ServiceTaxAmount.
Higher Education CessA secondary tax = ServiceTaxPer × 1 / 100, applied on ServiceTaxAmount.
CurrencyA configurable currency unit from the CurrencySet table used in financial transactions.
Advance EntryA salary advance paid to an employee, tracked for deduction during payroll processing.
Payroll / Net PayEmployee salary calculation: NetPay = Salary + OvertimeAmount - Deduction.

URS-CI-004 Tax Calculation Formulas (MUST BE PRESERVED EXACTLY)

The following formulas from frmCheckIn.vb::Compute() and frmCheckOut.vb::Calculate() must produce identical results:

Room Check-In/Out (Compute):
NoOfDays = (DateOUT == DateIN) ? 1 : (DateOUT - DateIN).Days
TotalRoomCharges = RoomCharges × NoOfDays
Discount = ((TotalRoomCharges + OtherCharges) × DiscountPer) / 100
SubTotal = TotalRoomCharges + OtherCharges - Discount
ServiceTaxAmount = Round((SubTotal × ServiceTaxPer) / 100, 2)
LuxuryTaxAmount = Round(((SubTotal + ServiceTaxAmount) × LuxuryTaxPer) / 100, 2)
GrandTotal = SubTotal + ServiceTaxAmount + LuxuryTaxAmount
Balance = GrandTotal - TotalPaid

Check-Out Additional (Calculate):
EducessTax = (ServiceTaxPer × 2) / 100
EducessTaxAmount = Round((ServiceTaxAmount × EducessTax) / 100, 2)
HEducessTax = (ServiceTaxPer × 1) / 100
HEducessTaxAmount = Round((ServiceTaxAmount × HEducessTax) / 100, 2)
For any given set of inputs, the calculated outputs must match the legacy system exactly (within floating-point rounding). frmCheckIn.vb, frmCheckOut.vb

URS-HR-009 Employee Payment/Salary Processing

System shall process employee salary with the following exact calculations:

Salary = (BasicSalary × PresentDays) / 30
OvertimeAmount = (TotalOvertimeMinutes × OvertimeRate) / 60
NetPay = Salary + OvertimeAmount - Deduction

Additional business rules:

  • Prevents duplicate payment for same employee on same date
  • Deduction cannot exceed advance amount
  • NetPay must be > 0
  • Auto-creates advance entry record for deductions (Amount=0, Deduction=entered value)
  • PaymentID auto-generated: "SP-" + 9 random digits
  • PresentDays calculated from attendance records (count of status='P' in date range)
 Salary calculated correctly per formula; duplicate payment prevented; advance entry auto-created; all validations enforced. frmEmployeePayment.vb, frmEmployeePaymentRecord1.vb, frmEmployeePaymentReport.vb
URS-HR-010 Salary Slip Generation & Reporting System shall generate individual salary slips for employees (replacing Crystal Reports rptSalarySlip) and batch salary slip reports. Salary slip generated with all payment details; printable; batch report available. frmSalarySlip.vb, frmSalarySlipsReport.vb
