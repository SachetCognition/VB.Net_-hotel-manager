1. Test Strategy Overview

Testing Pyramid

E2E Tests (5)
Integration Tests (10) & Regression Tests (5)
Unit Tests (90+) — Foundation Layer

The testing strategy follows the standard testing pyramid with the majority of tests at the unit level for fast feedback cycles. Integration tests verify cross-component behavior with a real database. E2E tests validate complete business workflows.

Test Environment

  • Unit Tests: In-memory, mocked dependencies using Moq. No database required.
  • Integration Tests: SQL Server (LocalDB or TestContainers) with EF Core migrations applied.
  • E2E Tests: Full API running with WebApplicationFactory, real SQL Server database.
  • Performance Tests: Dedicated test database with synthetic data (10,000+ records).

Test Naming Convention

{Category}-{Module}-{Number} — e.g., UT-CI-001 = Unit Test, Check-In module, test #001

2. Coverage Targets

  • Overall code coverage: ≥ 90%
  • Critical business logic (tax calculations, payroll): 100%
  • CRUD operations: ≥ 90% per entity
  • Validation logic: ≥ 95%
  • Edge cases: All identified boundary conditions covered
