Module 1: User Management

1.1 Overview

The system supports two user roles: Admin and User. Role-based access controls certain operations (e.g., stock management save/delete restricted by role as found in frmMainMenu.vb lines 363–371 and frmStock.vb).

1.2 Functional Requirements

FR-UM-001: Login

  • User provides Username, Password, and UserType (Admin/User).
  • System validates credentials against the database.
  • On success, user is redirected to the Main Menu with role-appropriate access.
  • On failure, an error message is displayed.

FR-UM-002: User Registration

  • New users can register with Username, Password, and UserType.
  • Duplicate username check is enforced.

FR-UM-003: Change Password

  • Authenticated users can change their password.
  • Old password verification is required.
  • New password is stored (legacy uses Base64 encoding via ModFunc.vb).

FR-UM-004: Login Details Viewing

  • Admin users can view login activity records.

FR-UM-005: Role-Based Access

FeatureAdminUser
Stock — Save/DeleteAllowedRestricted
User ManagementFull AccessLimited
Backup/RestoreAllowedRestricted
ActivationAllowedRestricted
Security Issue (Legacy): Passwords are stored using Base64 encoding (Encrypt/Decrypt functions in ModFunc.vb). This is NOT secure. The modernized system MUST use BCrypt password hashing.

Module 4: Check-In

4.1 Overview

The most complex module in the system. Source: Checkin and Check out/frmCheckIn.vb (2422 lines). Handles guest check-in, billing calculations, room assignment, and payment tracking.

4.2 Workflow

  1. Select guest from DataGridView (guests loaded from Guest table).
  2. Select room from available rooms.
  3. Set DateIn and DateOut.
  4. System performs billing calculation automatically.
  5. Optional: Select extra bed, currency, enter other charges, discount, etc.
  6. Enter payment amount.
  7. Save check-in record.

4.3 Billing Calculation (Compute Sub)

Step 1: NoOfDays = DateOut − DateIn (minimum 1 if same day)
Step 2: TotalRoomCharges = RoomCharges × NoOfDays
Step 3: Discount = ((TotalRoomCharges + OtherCharges) × DiscountPer) / 100   [truncated to integer via CInt]
Step 4: SubTotal = (TotalRoomCharges + OtherCharges) − Discount   [truncated to integer via CInt]
Step 5: ServiceTaxAmount = (SubTotal × ServiceTaxPer) / 100   [rounded to 2 decimal places]
Step 6: LuxuryTaxAmount = ((SubTotal + ServiceTaxAmount) × LuxuryTaxPer) / 100   [rounded to 2 decimal places]
Step 7: GrandTotal = SubTotal + ServiceTaxAmount + LuxuryTaxAmount   [truncated to integer via CInt]
Step 8: Balance = GrandTotal − TotalPaid   [truncated to integer via CInt]
Important: The LuxuryTax base includes ServiceTaxAmount (cascading tax). ServiceTax and LuxuryTax amounts are rounded to 2 decimal places using Math.Round, but GrandTotal and Balance are truncated to integers using CInt.

4.4 Room Availability Check

  • Cannot book if room has status "Reserved" in Temp_Reservation for overlapping dates.
  • Cannot book if room has status "Checked In" in CheckIn_Room for overlapping dates.
  • Date overlap logic: (RequestedDateIn < ExistingDateOut) AND (RequestedDateOut > ExistingDateIn)

4.5 Validations

  • DateOut must be ≥ DateIn.
  • TotalPaid cannot exceed GrandTotal.
  • Room must be selected.
  • Guest must be selected.

Module 5: Check-Out

5.1 Overview

Handles guest check-out with additional tax calculations. Source: Checkin and Check out/frmCheckOut.vb (809 lines).

5.2 Workflow

  1. Select checked-in guest from DataGridView (filtered by Status = "Checked In").
  2. System loads check-in data and recalculates billing.
  3. Additional education cess taxes are computed.
  4. Restaurant order PaymentDue is added to OtherCharges.
  5. Save checkout record.
  6. Update CheckIn_Room status to "Checked Out".
  7. Create Tax_Room record with additional tax details.
  8. Print invoice via Crystal Reports (rptInvoice_Room).

5.3 Additional Tax Calculations (Calculate Sub)

Base calculations: Same as Check-In (NoOfDays through GrandTotal)

Additional Taxes:
EducessTax = (ServiceTaxPer × 2) / 100   [rounded to 2 decimals]
EducessTaxAmount = (ServiceTaxAmount × EducessTax) / 100   [rounded to 2 decimals]
HEduCessTax = (ServiceTaxPer × 1) / 100   [rounded to 2 decimals]
HEducessTaxAmount = (ServiceTaxAmount × HEduCessTax) / 100   [rounded to 2 decimals]

5.4 Business Rules

  • Double checkout prevention: Checks if CheckInID already exists in Checkout_Room table.
  • Creates Checkout_Room record with BillNo, CheckInID, CheckOutDate, Notes, HotelID, CurrencyID.
  • Creates Tax_Room record with BillID, HEduTax, HEduTaxAmount, EducationalTax, EducationalTaxAmount.
  • Updates CheckIn_Room Status to "Checked Out".

NFR-002: Role-Based Access Control

  • Two roles: Admin and User.
  • Admin has full access to all modules including stock management, backup/restore, and user management.
  • User role has restricted access (stock save/delete disabled, backup/restore restricted).

NFR-006: Code Quality

  • Enable nullable reference types (C# strict typing).
  • Use using statements / IDisposable for all database connections.
  • Follow SOLID principles and separation of concerns.
  • Target >90% code coverage with unit and integration tests.

  • Restore from backup file with confirmation dialog.
